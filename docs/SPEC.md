# 仕様書

学生がふと抱いた問いから、それに迫る学問と、学内で会える師（先生）へとつなぐ Web アプリの仕様。企画の背景・根拠は企画案ドキュメント（「企画案：問いから、師に出会う」）を参照。

- 製品名：未定（PV では仮に「問いの星図」）
- 対象ユーザー：**大学生**（特に学部 1〜2 年生・研究室配属前の学生）

## 1. 解決する課題

- 何を学ぶかは、学ぶ前に決めなければならない。しかし専門用語や分野名が壁になり、自分の問いがどの学問につながるのかわからない（例：「なぜ人は協力するのか」が「ゲーム理論」につながると気づけない）。
- よき師との出会いは人生に大きく影響するが、在学中に出会えている学生は少ない。憧れの先生にいきなり会いに行くのは難しく、その前段階の「気軽に相談する → 分野を知る」を支えるものがない。

## 2. 利用者の体験

利用者は次の 4 段階をたどる。例の問いは「他者とは、自分にとってどういう存在なのだろうか。」。

| 段階 | 利用者が見るもの | 例 |
| --- | --- | --- |
| 問う | 日常の言葉で問いを書く | 「他者とは、自分にとってどういう存在なのだろうか。」 |
| 見渡す | 問いに近い分野が列で並ぶ。各分野に「ひとことで言うと」「よくある誤解」「あなたの問いの、この分野での呼び名」が付く | 哲学：当たり前を根っこから問い直す学問。誤解は「答えの出ない空論」。あなたの問いは「他者論」 |
| 出会う | 研究テーマとの意味の近さの順に、学内の先生が並ぶ | 文学部（哲学）の○○先生（現象学） |
| 深める | 問い・分野・用語・先生を差し込んだ質問文をコピーし、自分の AI（ChatGPT など）へ相談する | 「4.4 深めるのプロンプト」参照 |

## 3. 画面

| 画面 | 内容 |
| --- | --- |
| 問いの入力 | 問いの入力欄と例文。初回はモデルの読み込み状況を表示する |
| 結果（見渡す・出会う） | 分野の列。各列に分野カードと、その分野の先生の一覧 |
| 深める | 選んだ分野・先生を差し込んだ質問文のプレビューとコピーボタン。「ここから先はアプリの外」と明記する |
| このアプリについて | AI がどこで動いているか、問いを保存しないこと、データの出典（KAKEN） |

## 4. 機能要件

### 4.1 問う

- **F-1** 問いを自由記述で入力できる。最大 200 文字。
- **F-2** 例文を選んで入力できる。
- **F-3** 問いの文章はブラウザ内で埋め込みベクトル（数値）に変換し、**文章そのものはサーバーへ送らない**。
- **F-4** 初回はモデルのダウンロード進捗を表示する。2 回目以降はブラウザのキャッシュを使う。

### 4.2 見渡す

- **F-5** 問いとの意味の近さで分野を並べ、上位 **5 分野**を表示する。
- **F-6** 一致度の高い分野だけでなく、近いが違う分野も含める（「わざと隣の分野も見せる」）。
- **F-7** 各分野にカードを表示する。カードの項目は次のとおり。
  - ひとことで言うと
  - よくある誤解（**必須**）
  - あなたの問いの、この分野での呼び名（問いに最も近い専門用語）
- **F-8** カードの説明と誤解は分野ごとに人が用意し、確認済みのものだけを表示する。AI に生成させない。

### 4.3 出会う

- **F-9** 各分野の列に、研究テーマが問いに近い順で先生を最大 **3 人**表示する。
- **F-10** 先生ごとに、所属・研究テーマ・問いとの近さ（AI による推定であることを明示）・KAKEN の研究者ページへのリンクを表示する。
- **F-11** 表示する先生と研究テーマは、すべて実データ（KAKEN）に由来するものに限る。

### 4.4 深める

- **F-12** 選んだ分野・用語・先生をテンプレートに差し込んだ質問文を表示し、ワンクリックでクリップボードにコピーできる。
- **F-13** コピーの前に「この質問文はアプリの外の AI に送られる。送るかどうかはあなたが決める」と表示する。
- **F-14** アプリから外部 AI へ自動で送信しない。

テンプレート（`{ }` はアプリが差し込む）：

```text
最近、こんなことが気になっています。
{問い}
{分野}では「{専門用語}」という言葉で語られるそうです。

私の大学では、次の先生がこれに近いテーマを研究しています。
- {先生の名前}（{研究テーマ}）
- {先生の名前}（{研究テーマ}）

この先生たちの研究の方向性も手がかりにして、詳しく教えてください。
ほかの分野に面白いつながりがあれば、それも知りたいです。

それから、この分野の研究者が、自分の研究の面白さやロマンを語っている記事やインタビューがあれば、出典のURLを添えて引用・紹介してください。
見つからなければ、無理に作らないでください。
本や人の名前を出すときも、確かなものだけにしてください。
```

### 4.5 AI の見える化

- **F-15** アプリ内で AI が動く箇所（意味の近さの計算）には「AI」の表示を付ける。
- **F-16** 利用者自身の AI へ渡す画面は「アプリの外」と明記し、二つの AI を混同させない。

## 5. 非機能要件

| 分類 | 要件 |
| --- | --- |
| プライバシー | 問いの文章をサーバーに送らない・保存しない。ログイン機能を作らない。アクセスログにも問いを残さない |
| 性能 | 2 回目以降、問いの入力から結果表示まで 3 秒以内（デモ用 PC で計測） |
| 初回読み込み | モデルのダウンロードは 120MB 以内 |
| 対応環境 | PC 版の最新の Chrome / Edge / Safari。WebGPU がなければ WASM で動作する。スマートフォン対応はデモ後の課題とする |
| 可用性 | 審査期間（11/14〜11/15）に停止しない |
| データの扱い | KAKEN のデータは出典と加工の旨を明記する。利用者の操作ごとに KAKEN API を呼ばない |

## 6. AI の活用

| 項目 | 内容 |
| --- | --- |
| AI を使う理由 | 日常の言葉で書かれた問いと、専門用語で書かれた研究テーマは、キーワードでは一致しない。意味の近さで結びつけるには埋め込みモデルが必要 |
| 利用場面 | 問いと分野・研究テーマの意味の近さの計算（アプリ内では 1 か所のみ） |
| 使用モデル | 日本語対応の小さな埋め込みモデル（候補：Ruri v3 30m / multilingual-e5-small）。ブラウザ上で実行 |
| 使わないもの | クラウドの LLM API。長い対話は利用者自身の AI に任せる |

## 7. デモの範囲

- 対象は **1 大学**。先生のデータは KAKEN から取得する。
- 分野は**約 30 分野**。分野カードは各メンバーが専攻に近い分野を担当して作り、確認する。
- 授業（シラバス）や蔵書との連携は、余裕があれば追加する。

## 8. スコープ外

- ログイン・問いの履歴保存
- アプリ内での AI との対話（LLM による回答の生成）
- 先生へのアポイント・連絡機能
- 複数大学への対応
