# KAKEN API の使い方

先生と研究テーマのデータを KAKEN から取得するときの手引き。担当は #4（キー取得）、#5（規約）、データ取得の Issue 群。

> **確認の状態:** パラメータの仕様は NII 公開の定義書（[kaken_definition](https://bitbucket.org/niijp/kaken_definition/src/master/) の `KAKEN_API_parameters_document_Ja`）による。**実際に API を叩いて確かめた項目には「確認済」、まだの項目には「未確認」と書く。** 確かめたら書き換える。

## 1. 最初に守ること

- **API キー（appid）はリポジトリに書かない。** `.env` に `KAKEN_APPID=...` として置き、`.gitignore` に入れる。チャットやコメントにも貼らない。
- キーを他人に貸さない（利用細則 第5条）。使うのはデータ取得スクリプトを動かす人だけにする。
- **短時間に大量のアクセスをしない**（利用細則 第6条）。リクエストの間隔を空ける（目安: 1 秒に 1 回以下）。アプリの実行中には叩かず、**事前に取得して自前に保存**する。
- 取得結果を表示するときは、出典と加工した旨を載せる（DESIGN.md 10 章）。

規約の詳細は #4 と #5 のコメントを参照。

## 2. エンドポイント

| 何を探すか | URL |
| --- | --- |
| 研究課題（どんな研究か） | `https://kaken.nii.ac.jp/opensearch/` |
| 研究者（誰か） | `https://nrid.nii.ac.jp/opensearch/` |

すべてのリクエストに `appid=<キー>` が要る。キーなし・不正なキーはどちらも 403 になる（確認済。キーなしは `Exceeds allowed rate`、不正なキーは `Invalid APPID`）。

## 3. 共通のパラメータ

| パラメータ | 意味 | 備考 |
| --- | --- | --- |
| `appid` | API キー | 必須 |
| `kw` | フリーワード | URL エンコードする。ほかの検索条件を指定しないなら必須 |
| `rw` | 1 ページの件数 | 20, 50, 100, 200, 500 から選ぶ。既定は 20 |
| `st` | 取得の開始番号 | 既定は 1。ページ送りに使う |
| `lang` | 結果の言語 | `ja`（既定）か `en` |
| `format` | 返す形式 | **下の注意を参照** |
| `od` | 並び順 | 研究課題と研究者で値の意味が違う |

### 返す形式（`format`）は 2 つの API で違う

| API | 指定できる形式 | 既定 |
| --- | --- | --- |
| 研究課題 | `html5`, **`xml`** | html5 |
| 研究者 | `html5`, **`json`** | html5 |

- 指定を省略すると**画面用の HTML が返る**。必ず指定する。
- 研究課題の API に `format=json` は使えない。
- 別形式の定義書: [KAKEN_XML_definition](https://bitbucket.org/niijp/kaken_definition/src/master/)（課題の XML の項目）、`KAKEN_researcher_JSON_definition`（研究者の JSON の項目）。

### 取得できる件数の上限

| API | `st` の上限 |
| --- | --- |
| 研究課題 | 200,000 件 |
| 研究者 | **1,000 件** |

研究者の検索は、1 回の検索で**先頭の 1,000 件までしか取れない**。立命館大学の研究者は 1,000 人を超えるおそれがあるので、**条件を分けて複数回検索する**（所属の部局 `qq`、職名 `qs`、氏名の読み順 `od` など）。→ 6 章

## 4. 研究課題の検索（`kaken.nii.ac.jp/opensearch/`）

| パラメータ | 絞り込む項目 | 補足 |
| --- | --- | --- |
| `qa` | 研究課題名 | URL エンコード |
| `qb` | 研究課題番号 | |
| `qc` | 研究種目 | URL エンコード |
| `qd` | 審査区分／研究分野 | URL エンコード。**30 分野との対応表の元データ**（DESIGN.md 11 章） |
| `qe` | 研究機関 | 立命館大学で絞るときに使う |
| `qf` | キーワード | |
| `qg` | 研究者の姓名 | |
| `qh` | 研究者の所属機関 | |
| `qm` | 研究者番号 | |
| `s1`, `s2` | 助成期間の開始・終了年度（From, To） | 数字のみ。From > To はエラー |
| `o1` | 期間の判定方法 | 1=開始年度, 2=終了年度, 3=期間の一部を含む, 4=期間の全部を含む |
| `c1` | ステータス | 複数指定可。例: `adopted`（採択）, `project_closed`（完了） |
| `c2` | 研究者の役割 | 複数指定可。例: `principal_investigator`（研究代表者） |
| `c6` | 課題の種別 | 複数指定可。例: `project`（研究課題） |
| `od` | 並び順 | 1=適合度, 2=開始年が新しい順（既定）, 3=古い順, 4=配分額が多い順, 5=少ない順 |

ほかに、配分額 (`s3`)、報告書の種類 (`c3`)、評価 (`s4`, `s5`)、成果の種別 (`c5`) などがある。全項目は定義書を参照。

## 5. 研究者の検索（`nrid.nii.ac.jp/opensearch/`）

| パラメータ | 絞り込む項目 |
| --- | --- |
| `qg` | 研究者の姓名 |
| `qm` | 研究者番号 |
| `qh` | 所属機関 |
| `qq` | 部局 |
| `qs` | 職名 |
| `qa`, `qb`, `qc`, `qd`, `qe`, `qf` | 研究課題名・番号・研究種目・審査区分・研究機関・キーワード（課題側の条件） |
| `s1`, `s2`, `o1` | 研究期間（年度）。研究課題側と同じ意味 |
| `od` | 並び順。1=適合度, 2〜3=カナ順（昇順・降順）, 4〜5=アルファベット順, 6=課題数が少ない順, 7=課題数が多い順（既定） |

## 6. 検索条件の書き方（`kw` などに入れる文字列）

- 空白で区切ると AND。大文字の `OR`、`NOT` も使える。括弧は使えない。
- `"..."` で囲むとフレーズ検索。
- 末尾に `*` で前方一致。後方一致・中間一致はできない。
- 人名は、姓と名の間にスペースを入れずに入れると完全一致する（例: `山田一`）。
- 日本語は URL エンコードが必要。

## 7. リクエスト例

> キー部分は `$KAKEN_APPID` とする。実行前に環境変数へ入れる。

**立命館大学の研究課題を 1 ページ分、XML で取る**

```bash
curl -s "https://kaken.nii.ac.jp/opensearch/?appid=$KAKEN_APPID&qe=%E7%AB%8B%E5%91%BD%E9%A4%A8%E5%A4%A7%E5%AD%A6&format=xml&rw=100&st=1"
```

**立命館大学の研究者を JSON で取る（先頭 100 件）**

```bash
curl -s "https://nrid.nii.ac.jp/opensearch/?appid=$KAKEN_APPID&qh=%E7%AB%8B%E5%91%BD%E9%A4%A8%E5%A4%A7%E5%AD%A6&format=json&rw=100&st=1"
```

どちらも「未確認」。`qe` / `qh` に `立命館大学` を入れたときの絞り込みの効き方（表記ゆれ、別名の機関が混じらないか）は、実際に叩いて確かめる。

## 8. データ取得スクリプトの方針

1. キーは環境変数 `KAKEN_APPID` から読む。
2. リクエストの間隔を空ける（1 秒以上）。403 や 429 が返ったら待って再試行する。連続して失敗したら止める。
3. 研究者は 1 回で 1,000 件までなので、部局・職名・読み順で**検索を分割**し、研究者番号で重複を除く。
4. 取得した生データは `data/` 配下のローカル（`.gitignore` 対象）に置く。**生データはリポジトリに入れない**（DESIGN.md 10 章）。
5. リポジトリに入れるのは、アプリに必要な最小限の加工済みデータだけにする。
