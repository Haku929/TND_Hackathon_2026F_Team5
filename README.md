## アプリ名

（未定。PV では仮に「問いの星図」）

## 概要

学生がふと抱いた問いから、それに迫る学問と、学内で会える師（先生）へとつなぐ Web アプリ。「気軽に AI に相談する → 分野を知る → 師に出会う」という道のりを支える。

## 対象ユーザー

- 対象: 大学生（デモでは立命館大学の先生のデータを使う）
- 想定する場面: 学部 1〜2 年生が、授業や日常でふと抱いた問いを、どの学問で・どの先生のもとで深められるかを知りたいとき。研究室やゼミを選ぶ前の段階。

## 背景・解決する課題

- **学ぶ前に、学ぶものを選ばなければならない。** 専門用語や分野名が壁になり、自分の問いがどの学問につながるのかわからない（例：「なぜ人は協力するのか」が「ゲーム理論」につながると気づけない）。
- **よき師との出会いは人生を動かすが、出会えている学生は少ない。** 在学中によき師に恵まれた大卒者は 100 人に 14 人（[Gallup-Purdue Index, 2014](https://news.gallup.com/opinion/gallup/173624/gallup-purdue-reveal-findings-college-graduates.aspx)）。
- **憧れの先生には、いきなり会いに行きにくい。** その前段階の「気軽に相談する → 分野を知る」を支えるものがない。

## AIの活用

| 項目 | 内容 |
| --- | --- |
| AIを使う理由 | 日常の言葉で書かれた問いと、専門用語で書かれた研究テーマは、キーワードでは一致しない。意味の近さで結びつけるには埋め込みモデルが必要 |
| 利用場面 | 問いと分野・用語・研究テーマの意味の近さの計算（アプリ内で AI が動くのはこの 1 か所） |
| 使用モデル / API | 多言語対応の小さな埋め込みモデル（multilingual-e5-small）を Transformers.js でブラウザ上で実行。クラウドの LLM API は使わない |

## 主な機能

| 機能 | 説明 | 状態（実装 / モック） |
| --- | --- | --- |
| 問う | 日常の言葉で問いを書く。問いの文章はブラウザ内で数値に変え、サーバーへ送らない | 未着手 |
| 見渡す | 問いに近い分野を並べ、「ひとことで言うと」「よくある誤解」「あなたの問いの、この分野での呼び名」を示す | 未着手 |
| 出会う | 研究テーマが問いに近い順に、学内の先生を並べる（KAKEN の実データ） | 未着手 |
| 深める | 問い・分野・用語・先生を差し込んだ質問文をコピーし、自分の AI に相談できる | 未着手 |

## 独自性（新規性）

研究者を意味で探す仕組みはすでにある（[SeedsSearch+ AI](https://en.nagoya-u.ac.jp/news/seedssearch_ai_research_database_launched.html)、[OpportunityMatch](https://bayes-centre.ed.ac.uk/access-expertise/opportunitymatch/introducing-opportunitymatch) など）が、いずれも企業や研究者どうしの連携向け。このアプリは**学生の問いから始まり、複数の分野を見渡し、学内の師にたどり着く**。汎用 AI と違い、実在する自分の大学の先生につながり、実在しない人や本は出てこない。

## 期待される効果（インパクト）

- 自分の問いと学問のつながりに気づき、学部をまたいだ学びが生まれる
- 研究室・ゼミ選びのミスマッチが減る
- 先生に会いに行く前に、分野のことばを知った状態で相談できる

## セキュリティ対策

詳細は [設計書の「セキュリティ設計」](docs/DESIGN.md#9-セキュリティ設計) を参照。

| 想定する攻撃 | 対策 | テスト方法 / 結果 |
| --- | --- | --- |
| XSS | React の自動エスケープ、CSP で外部スクリプトを禁止 | 時間の都合上外部スクリプトのみ。wasm周りは無制限に許可している |
| SQL インジェクション | パラメータ化クエリ。API は数値の配列しか受け取らない | APIの修正とともに実装済み |
| 不正・過大なリクエスト | ベクトルの長さ・型・ノルム・本文サイズの検証、回数制限 | APIの不備を修正し、完全なjsonでなくても400を返すようにした。Vercelの設定で大量アクセスを遮断するよう設定したが無料枠の上限があるようなので注意。Vercelのスクリーンショットはdocs/security　に入れた |
| 問いの漏えい | 問いをサーバーに送らない・URL に入れない・ログに残さない | 上に同じくスクリーンショットを入れた |
| プロンプトインジェクション | 質問文に差し込むのは確認済みデータのみ。差し込む文字列を整形 | 未実施 |
| 取得スクリプトのAPIキー流出 | 環境変数またはGit対象外の `.env` から読み込み、キー入りURLをログ・キャッシュに保存しない | エラー非表示・応答へのキー混入拒否を通信なしテストで確認。提出対象のキー混入チェックも通過（#21） |

## UI・UX の工夫

- 分野カードには「よくある誤解」を必ず載せ、分野の印象を一目で正す
- 一致度の高い分野だけでなく、近いが違う分野もわざと見せ、分野をまたいだ発見を生む
- アプリ内で AI が動く箇所には「AI」と表示し、利用者自身の AI へ渡す画面は「アプリの外」と明記して、二つの AI を混同させない
- ログイン不要。問いは保存しない
- スマートフォンを主な利用環境として設計。モデルの読み込み中も問いを入力でき、待ち時間を感じさせない

## セットアップ

Node.js 22 以上が必要（バージョンは `.nvmrc` を参照）。

```bash
npm install
cp .env.example .env.local   # 値はチームから受け取って書き込む
npm run dev                  # http://localhost:3000
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動 |
| `npm run build` | 本番用にビルド |
| `npm run lint` | ESLint でチェック |
| `npm run format` | Prettier で整形（`format:check` は確認のみ） |
